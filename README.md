Server
=====

Code relating to the server side operations is stored in either functions/api or shared/ directories.

I used serverless functions hosted by cloudflare to run the server side code because you only pay for what you actually use past a certain threshold and you don't have to turn them on/off to save money as they handle that automatically.

Database
=====

SQL queries for interacting with the database are also located in functions/api and shared/ the structure of the database is defined in infra/d1.tf

I used D1 because it can easily be integrated to work with an existing cloudflare pages project.

Web Frameworks
=====

Code for the frontend is in src/

I used react because you can reuse existing components and it can help with creating user interfaces quickly.

Continuous Integration
=====

I used terraform which is an IaC devops tool that allowed me to create resources programmatically. The resources that I created and maintained using terraform included the cloudflare pages project which needed an additional binding defined for the D1 database and the GitHub repository that it is connected to and would pull the sourcecode from, the D1 database itself was created using terraform. The only thing that I created manually was the S3 bucket that securely stores the current terraform state file which should be kept secret as it contains private keys. The advantage of using terraform is that my entire project infrastructure is now version controlled in a GitHub repository, so I can rollback to previous infrastructure easily if something breaks, I can recreate the entire project's infrastructure with ease if I want to, and any changes to this infrastructure can be reviewed later. Tools like terraform are invaluable in devops and continuous integration continuous deployment pipelines as it declaratively automates the scaling and maintenance of all cloud resources in your application.

To automate the deployment of this infrastructure I used a GitHub actions pipeline. How it works is whenever I push changes to the repository the action is automatically run. It first initializes terraform, it then makes a full plan of the infrastructure it is going to create modify or destroy, and it then applies these planned changes to the infrastructure. GitHub actions can be integrated with GitHub to pass secrets such as api keys over to terraform as environment variables. This implements one of the core devops practices needed which is Continuous Integration and Continuous Deployment because this system ensures that both the code and infrastructure of the project can be added to production automatically.

My continuous integration pipeline involved using Terraform and GitHub actions. Terraform source files are stored in infra/ and the GitHub action used is in .github/workflows/deploy.yaml

Deployment
=====

Deployment is handled by Cloudflare pages. When you push to the main branch cloudflare automatically clones and builds the source code into a working web application, it is then deployed to the live website.

Maintainability
=====

A serverless backend eliminates most operational burden of having to manage a full server, the Observability tool provides fast real time logs for troubleshooting, Terraform's Infrastructure as Code ensures consistent environments.

Scalability
=====

Cloudflare’s global edge network automatically scales with demand as long as you can pay for it
Serverless functions scale per request and are not paid until a certain threshold is reached
Using a CI/CD pipeline allows fast, repeatable deployments.

Observability
=====

For some basic observability and logging in the application, I used the serverless function real time logs which show live error messages that are generated by the server, this allowed me to debug issues with website performance as well as giving information about any requests that are sent to the server. Better logging stacks such as Grafana or Sentry could have been used here, but I decided to go for a more simple approach, as I don't think that extensive logging was really needed for this project and this still demonstrates monitoring and feedback from the application.

All logging is done in serverless functions in functions/api

Security
=====

Cloudflare provides free SSL certification and ddos protection by default. A fully automated declarative pipeline reduces human error in introducing vulnerabilities to the system. Secrets managed through cloudflare and GitHub never touch the sourcecode, stopping the wrong people from using them.
